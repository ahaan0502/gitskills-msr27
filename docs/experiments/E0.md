# E0 - Data preparation

Status: complete. See [E0 results](../results/E0-results.md) for all measurements and output summaries.

## Objective

Establish the reproducible dataset snapshot, parser agreement, date-coverage audit, representative skill table, and reusable sampling signals required by later experiments. Source data and large generated artifacts remain outside Git.

## Methodology

1. Read the project plan and restrict work to setup/E0.
2. Pin and download the Hugging Face dataset revision. Convert the public SQLite sample to per-table Parquet using the same table layout as the mirror.
3. Parse representative SKILL.md contents and compare parser fields against the dataset's own fields.
4. Audit first-commit and repository dates with Gate A, preserving no-date, pre-window, and in-window categories and location-class coverage.
5. Build one parsed row per distinct representative content using streamed batches.
6. Create separate catalog, template, and bulk-repository signals and a deterministic per-repository rank. Keep signals separate for later sensitivity analyses.
7. Validate row counts, distinct hashes, schema, rank bounds, and flag integrity.

## Parser specification

- `spec_valid` means a YAML mapping with non-empty name and description.
- Closing front-matter fences accept three or more dashes.
- YAML errors may recover line-level name/description values, but `frontmatter_valid` remains false and `fm_recovered` records the recovery.
- Body character counting preserves the dataset's CRLF convention.

## Gate A rules

Use the format start of October 2025 and collection end of July 2026. Report coverage by location class and distinguish canonical, skills-directory, and other locations. Do not treat dated records as representative of the full population when coverage is structurally uneven.

## Signal definitions

- Catalog signal: path/name heuristic identifying likely catalog or index content.
- Template signal: normalized content repeated across at least the configured repository threshold.
- Bulk-repository signal: repository skill count at or above the configured threshold.
- Repository rank: deterministic ordering used for later per-repository caps.

## Scope boundary

E0 does not test language distributions, authorship, structural convergence, phrasing, semantic topics, or integration effects. Those belong to E1-E6.
